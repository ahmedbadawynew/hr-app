# حزمة التطبيق المثبّت + إشعارات الموبايل (Firebase FCM)

الحزمة دي صفحة بسيطة بتفتح برنامجك (Apps Script) جواها، وبتتثبت على الموبايل كتطبيق، وبتستقبل إشعارات Push.

## محتويات الحزمة
- `index.html` — الصفحة الرئيسية (بتفتح البرنامج + بتتعامل مع الإشعارات). **بتحل محل** `wrapper_index.html` القديم.
- `config.js` — **الملف الوحيد اللي بتعدّل فيه** (رابط البرنامج + إعدادات Firebase).
- `manifest.json` — اسم التطبيق وألوانه وأيقوناته (غيّر `name` و`short_name` لو حابب).
- `firebase-messaging-sw.js` — يستقبل الإشعارات والتطبيق مقفول.
- `icons/` — أيقونات مؤقتة. استبدلها بلوجو الشركة بنفس الأسماء والأحجام (192 و512 و512 maskable و180).

## الخطوة 1: مشروع Firebase (مجاني)
1. ادخل https://console.firebase.google.com ← **Add project** (تقدر توقف Google Analytics).
2. من الصفحة الرئيسية للمشروع دوس أيقونة الويب `</>` ← سمّي التطبيق ← **Register app** (من غير Hosting).
3. هيظهر لك `firebaseConfig` (apiKey, authDomain, projectId, ...). انسخ القيم دي في `config.js` جوه `firebase: { ... }`.
4. **Project settings ← Cloud Messaging ← Web configuration ← Web Push certificates ← Generate key pair**. انسخ المفتاح الطويل في `vapidKey` داخل `config.js`.
5. تأكد إن **Firebase Cloud Messaging API (V1)** مفعّلة في نفس الصفحة (بتبقى مفعّلة افتراضيًا في المشاريع الجديدة).

## الخطوة 2: حساب الخدمة (Service Account)
1. **Project settings ← Service accounts ← Generate new private key** ← هينزل ملف JSON.
2. افتح الملف بأي محرر نصوص وانسخ **محتواه كامل**.
3. **متنشرهوش على GitHub ولا ترفعه مع الصفحة** — ده سر. هتلصقه في البرنامج نفسه في الخطوة 4.

## الخطوة 3: استضافة الصفحة (HTTPS إجباري)
أسهل طريقة: **GitHub Pages**
1. اعمل حساب على github.com ← **New repository** (مثلًا `hr`) ← Public.
2. ارفع محتويات هذا المجلد (index.html و config.js و manifest.json و firebase-messaging-sw.js ومجلد icons) — بعد ما تعدّل `config.js`.
3. **Settings ← Pages ← Source: Deploy from a branch ← main / root ← Save**.
4. بعد دقيقة هيظهر الرابط: `https://USERNAME.github.io/hr/` (ده **رابط التطبيق المثبّت**).

> في `config.js` لازم `appUrl` يكون رابط نشر البرنامج (ينتهي بـ `/exec`) والنشر بإعداد **Anyone**.
> لو عملت **New deployment** (مش New version) الرابط بيتغيّر — حدّثه في `config.js`.

## الخطوة 4: الإعداد داخل البرنامج (كأدمن)
**إعدادات النظام ← إشعارات Push للموبايل**:
1. الصق **رابط التطبيق المثبّت** (`https://USERNAME.github.io/hr/`).
2. الصق **محتوى ملف الـ JSON** كامل.
3. **حفظ** — لازم تشوف "مفعّل (مشروع: ...)" في الحالة.

## الخطوة 5: على الموبايل
- **أندرويد (Chrome):** افتح رابط التطبيق المثبّت ← القائمة ⋮ ← **تثبيت التطبيق / Add to Home screen**.
- **آيفون (Safari):** افتح الرابط ← زر المشاركة ← **Add to Home Screen**. الإشعارات على آيفون بتشتغل **بس** من التطبيق المثبّت على الشاشة الرئيسية وبنظام **iOS 16.4 أو أحدث**.
- افتح التطبيق من الأيقونة ← سجّل دخول ← دوس 🔔 **تفعيل الإشعارات** (أو من الملف الشخصي: "تفعيل إشعارات الجهاز") ← **Allow**.
- من إعدادات النظام دوس **"إرسال إشعار تجربة لأجهزتي"**.

## إمتى بتوصل إشعارات؟
- **للمسؤولين:** لما موظف داخل نطاقهم يبعت طلب تعديل بيانات (أصحاب صلاحية اعتماد الطلبات)، أو استفسار جديد (أصحاب صلاحية الرد على الاستفسارات).
- **للموظف:** لما طلبه يتعتمد أو يترفض، أو يتم الرد على استفساره.
- كل موظف ممكن يسجّل لحد 5 أجهزة، والجهاز بيتشال تلقائيًا عند تسجيل الخروج.


## رسالة تثبيت التطبيق
- أول ما حد يفتح الصفحة المستضافة من المتصفح (مش من التطبيق المثبّت) بتظهر له رسالة أسفل الشاشة:
  - **أندرويد / كروم / إيدج:** زرار **تثبيت** مباشر. لو المتصفح ما بعتش حدث التثبيت بعد 4 ثواني بتظهر تعليمات يدوية (⋮ ← تثبيت التطبيق).
  - **آيفون:** تعليمات «زر المشاركة ← إضافة إلى الشاشة الرئيسية».
- لو قفلها (✕) مش هتظهر له تاني لمدة 7 أيام. وبتختفي تمامًا لما يفتح من التطبيق المثبّت.
- **مهم:** الصفحة لازم تكون على HTTPS، وملف `manifest.json` والأيقونات موجودين، والـ Service Worker متسجّل — وده كله متظبط في الحزمة.
- الرسالة بتظهر من **الصفحة المستضافة** بس. لو الموظف فتح رابط Apps Script مباشرة هتظهر له في البرنامج نفسه رسالة تدلّه يفتح رابط التطبيق (لو سجّلت رابط التطبيق في إعدادات النظام).


## الدخول بالبصمة
- بيشتغل **بس من التطبيق المثبّت / الصفحة المستضافة** (مش من رابط Apps Script مباشرة)، وبشرط تسجيل **رابط التطبيق المثبّت** في إعدادات النظام.
- الموظف يفعّله من **الملف الشخصي ← تفعيل الدخول بالبصمة**: بيكتب كلمة مروره الحالية، وبعدها الجهاز يطلب بصمته (أو الوجه أو قفل الشاشة).
- بعد كده في شاشة الدخول يظهر زرار **👆 الدخول بالبصمة**.
- التفعيل **لكل جهاز** (حد أقصى 3 أجهزة للموظف)، وبيتلغي تلقائيًا لما كلمة المرور تتغيّر أو الأدمن يعيد تعيينها، أو بعد 90 يوم من عدم الاستخدام، أو لما الموظف يوقفه.
- البصمة بتتحقق **على الجهاز** نفسه، والسيرفر بيتحقق من توكن عشوائي خاص بالجهاز (مخزّن عنده مُجزّأ). يعني هو "قفل بالبصمة" على دخول الجهاز المحفوظ، مش بديل لكلمة المرور على جهاز تاني.

## لو الإشعارات مبتوصلش
1. الحالة في إعدادات النظام لازم تكون "مفعّل" وعدد الأجهزة أكبر من صفر بعد ما تفعّل الإشعارات على الموبايل.
2. تأكد إنك فاتح البرنامج من **الصفحة المستضافة/التطبيق المثبّت** مش من رابط Apps Script مباشرة.
3. تأكد إن إذن الإشعارات للموقع **Allowed** في إعدادات المتصفح.
4. أي خطأ بيظهر عند "إرسال إشعار تجربة" اقرأه — غالبًا بيقول المشكلة (مفتاح غلط، مشروع غلط...).
5. بعد أي تعديل في الصفحة المستضافة افتحها مرة وحدّث (Refresh) عشان الـ Service Worker يتحدّث.
